# Roadmap: JoinQuant API & Strategy Knowledge Base

## Overview

Two phases that deliver a working AI-queryable knowledge base. Phase 1 builds the scraper that logs in to JoinQuant, pulls all strategy code and API docs, and deposits them into a structured SQLite database. Phase 2 builds the query layer and MCP server that exposes those docs to AI hosts via focused, LLM-oriented tools. Nothing in Phase 2 can be built until Phase 1's scraper has validated data in the database.

## Phase Details

### Phase 1: Scraper + Schema
**Goal**: A populated, verified SQLite database containing all scraped JoinQuant API docs and strategy code — the single source of truth the MCP server will serve
**Depends on**: Nothing (first phase)
**Requirements**: SCRP-01, SCRP-02, SCRP-03, SCRP-04, SCRP-05, SCRP-06, SCRP-07, SCRP-08, DB-01, DB-02, DB-03, DB-04, DB-05
**Success Criteria** (what must be TRUE):
  1. Running `python run_scrape.py` completes without error and the SQLite file exists with non-zero row counts in both `api_docs` and `strategies` tables
  2. API doc rows contain structured parameter data (not a text blob) — each parameter is a distinct queryable record with name, type, and description fields
  3. Strategy rows contain name, category, code content, and description fields populated from the "经典策略学习" sidebar navigation
  4. Running the scraper a second time produces identical row counts with no duplicates (idempotent upsert behavior confirmed)
  5. The scraper loads a persisted session from `auth.json` on the second run and does not re-execute the login flow
**Plans:** 5 plans (4 complete, 1 gap closure)

Plans:

- [x] 01-02-PLAN.md — Headed discovery spike for CSS selectors and auth module
- [x] 01-03-PLAN.md — API documentation scraper (4 target pages)
- [x] 01-04-PLAN.md — Strategy scraper and run_scrape.py pipeline orchestrator
- [ ] 01-05-PLAN.md — Gap closure: valid credentials + end-to-end strategy scraping verification

### Phase 2: Query Layer + MCP Server
**Goal**: A FastMCP server running over stdio that an AI host (Claude Desktop) can connect to and use to look up accurate JoinQuant API documentation on demand
**Depends on**: Phase 1
**Requirements**: MCP-01, MCP-02, MCP-03, MCP-04, MCP-05, MCP-06
**Success Criteria** (what must be TRUE):
  1. Claude Desktop can be configured to connect to the MCP server and the connection succeeds without errors
  2. Asking Claude "what parameters does get_price take?" causes Claude to call the lookup tool and return the correct parameter list from the database — not a hallucinated answer
  3. A keyword search for a Chinese term (e.g., "融资融券") returns matching API doc entries with all structured fields present in a single response
  4. Querying a function name that does not exist returns an explicit not-found message, not an empty result or Python exception
  5. Section-scoped search returns only results from the specified API section, and the tool description is written so an LLM knows when to use it
**Plans:** 2/2 plans executed

Plans:
- [x] 02-01-PLAN.md — FastMCP server with all 6 tools, unit tests, and read-only DB connection
- [x] 02-02-PLAN.md — Integration verification against real DB and Claude Desktop checkpoint
